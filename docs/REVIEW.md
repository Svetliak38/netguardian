## Ключевые находки подробно

### 1. TCPView не скачивался никогда

```python
urls = [
    "https://download.sysinternals.com/files/Tcpview.zip",   # 404
    "https://live.sysinternals.com/Tcpview.zip",             # 404
]
```

Официальный файл называется `TCPView.zip` (заглавные `TCPV`), а прямой бинарник —
`https://live.sysinternals.com/Tcpview.exe`. Лог `logs/guardian.log` это
подтверждал: `HTTP Error 404: Not Found` на каждой попытке. В 3.0 сначала
пробуется прямой подписанный EXE, затем ZIP; подпись проверяется до запуска.

### 2. Запись `hosts` без страховки

`HostsManager.apply_profile()` читал файл, склеивал новую строку и открывал
`hosts` на запись `'w'`. Любой сбой между `open()` и `write()` оставлял
системный файл пустым или обрезанным, а резервной копии не было. Плюс
`encoding='mbcs'` перекодировал комментарии.

В 3.0: копия в `backups/`, временный файл в том же каталоге, `fsync`,
`os.replace`, перечитывание и сверка блока. При расхождении — возврат исходных
байтов.

### 3. «Валидация» проверяла не тот маршрут

```python
ip = resolver.resolve_domain(primary_dom, ...)
if ip:
    ok, details = SSLValidator.validate(primary_dom, ...)
```

`ip` использовался только как признак «что-то нашли», а `validate()` заново
разрешал имя через систему. Если `hosts` ещё не изменён, проверялся системный
DNS; если изменён — вообще любой из адресов. В 3.0 TLS-соединение идёт на
закреплённый IP, SNI и проверка имени — на домен.

### 4. Старая строка в `hosts` сильнее нового фикса

Windows берёт **первое** совпадение. В живом `hosts` на тестовой машине была
ручная строка `185.199.108.133 github.com` выше блока NetGuardian. Профиль
«применялся», но ничего не менял. 3.0 находит такие строки и отказывается
писать, пока они не удалены (или не передан `--force`).

### 5. `FIN_WAIT_2` не распознавался

Состояние проверялось регуляркой `[A-Z_]+`, которая не допускает цифру, а
`FIN_WAIT_1`/`FIN_WAIT_2` — именно с цифрой. Список состояний был жёстко
зашит двумя значениями. 3.0 использует `[A-Z][A-Z0-9_]*` и настраиваемый
`stuck_states`.

### 6. `nslookup` как парсер DNS

Разбор `Address(es):` ловил и адрес самого DNS-сервера, а фильтр
`ip.startswith(('192.', '10.', '172.'))` выбрасывал легитимные публичные
адреса `172.32+`. Локализованный вывод `nslookup` тоже ломал регулярку. 3.0
говорит по DNS-протоколу: свой запрос A, проверка ID ответа и адреса
отправителя, TCP-fallback при усечении.

## Что сохранено

- Формат `routes.json` и три профиля по умолчанию.
- Формат маркеров `# === NETGUARDIAN FIX (profile) [ts] BEGIN/END ===`,
  поэтому блоки 2.3 читаются и удаляются.
- Номера пунктов интерактивного меню (1–6), плюс новые 7–9 и `L`.
- Поведение «сначала кэш, затем статика, затем DNS» для `static_first`.
