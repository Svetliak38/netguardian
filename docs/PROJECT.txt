1. АННОТАЦИЯ
--------------------------------------------------------------------------------

NetGuardian — консольная утилита для Windows, которая исправляет ситуацию,
когда домен резолвится в недоступный IP-адрес и приложение зависает на
установке соединения. Программа находит адрес, реально принимающий TCP,
закрепляет его за доменом в системном файле hosts, проверяет маршрут по
TLS и автоматически откатывает изменения при ошибке.

Проект начался как прототип v2.3 на 670 строк. В версии 3.0 ядро
переработано: выделен пакет из 15 модулей, добавлены атомарная запись
hosts, резервные копии, откат, собственный DNS-клиент, проверка подписи
TCPView, CLI с JSON и кодами возврата, 91 модульный тест и сборка
портативной и однофайловой версий.

В версии 3.1 добавлены профили github_access и gitlab_access с отдельными
списками адресов для каждого домена (github.com, api, raw, gist, codeload,
gitlab.com, registry.gitlab.com), новое поле domain_candidates и 118 тестов.


--------------------------------------------------------------------------------
2. ПРОБЛЕМА И АКТУАЛЬНОСТЬ
--------------------------------------------------------------------------------

Типичный сценарий: интернет работает, но конкретная программа (лаунчер,
клиент обновлений, git, браузер) не подключается. Диагностика показывает
одно из двух:

  - домен резолвится в адрес, который не отвечает на 443;
  - соединение устанавливается, но TLS не проходит (подмена/перехват).

Причины бывают разными: устаревшая запись в hosts, ошибка локального DNS,
недоступный edge CDN, прокси или антивирус. Пользователь часто не знает,
что именно сломано, и начинает менять DNS, отключать антивирус или
переустанавливать приложение.

NetGuardian автоматизирует конкретный и проверяемый шаг: подобрать
рабочий адрес, закрепить его и убедиться, что TLS на этом адресе
валиден. При этом все изменения обратимы и не затрагивают чужие записи.

3. ЦЕЛЬ ПРОЕКТА
--------------------------------------------------------------------------------

Создать готовый к использованию инструмент, который:

  1) находит доступный IP для заданного набора доменов;
  2) безопасно и обратимо закрепляет его в hosts;
  3) проверяет результат по TLS;
  4) объясняет пользователю, что произошло и что делать;
  5) поставляется как готовый релиз с документацией и тестами.

5. ЦЕЛЕВАЯ АУДИТОРИЯ
--------------------------------------------------------------------------------

  - пользователи Windows, у которых конкретное приложение не подключается,
    а переустановка и смена DNS не помогают;
  - системные администраторы, которым нужен воспроизводимый и обратимый
    способ закрепить маршрут;
  - разработчики, которым нужен пример аккуратной работы с системным
    файлом hosts и сетевой диагностики на стандартной библиотеке Python.

Инструмент не рассчитан на массовое обходное решение и не заменяет VPN.


--------------------------------------------------------------------------------
6. РЕАЛИЗОВАННЫЕ ВОЗМОЖНОСТИ
--------------------------------------------------------------------------------

Профили:
  - четыре профиля из коробки (Microsoft, игровой сервис, GitHub, GitLab);
  - отдельные списки IPv4 для каждого домена (domain_candidates);
  - произвольные профили в routes.json;
  - стратегии static_first, dns_discovery_only, static_only, system_dns;
  - список портов, ожидаемые издатели сертификата, подсказки процессов.

Поиск и проверка:
  - кэш адресов с TTL и проверкой живости;
  - собственный DNS-клиент (A-записи, UDP + TCP fallback);
  - TCP-проба каждого кандидата;
  - TLS-проверка по закрепленному IP, SNI домена, издатель, срок действия.

Работа с hosts:
  - отдельный помеченный блок на профиль;
  - копия перед каждой записью, ротация копий;
  - атомарная запись и проверка после записи;
  - автоматический откат при неудачной TLS-проверке;
  - обнаружение конфликтов (включая блоки других профилей);
  - удаление только своих блоков;
  - восстановление из копии.

Диагностика и интерфейс:
  - diag с вердиктами ok/dns/tcp/tls/hosts;
  - scan зависших соединений;
  - status, список копий, config, lang;
  - интерактивное меню на русском и английском;
  - JSON-вывод и коды возврата для скриптов;
  - логи с ротацией.

Поставка:
  - портативная сборка (не распаковывается при старте);
  - однофайловая сборка;
  - исходники, тесты, сборка, иконка, версия PE-файла;
  - документация в .md и .txt.

7. АРХИТЕКТУРА (КРАТКО)
--------------------------------------------------------------------------------

    CLI / меню
       |
       +--> config (routes.json) --> Resolver --> Cache
       |                              |
       |                              +--> static / DNS / system --> TCP
       |
       +--> HostsFile --> backup --> atomic write --> verify
       |                                  |
       |                                  +--> rollback on error
       |
       +--> sslcheck (pinned IP + SNI) --> ok / rollback

Пакет разделен по зонам ответственности: config, paths, hosts, resolver,
scanner, sslcheck, diagnostics, tcpview, security, i18n, log, fsutil,
errors, ui, cli. Точка входа guardian.py остается совместимой с v2.3.

Подробности, форматы и алгоритмы — в docs\HOW-IT-WORKS.txt.


--------------------------------------------------------------------------------
8. НАДЕЖНОСТЬ И БЕЗОПАСНОСТЬ
--------------------------------------------------------------------------------

  - Атомарная запись: временный файл + fsync + os.replace.
  - Копия перед изменением и восстановление.
  - Проверка после записи; откат при ошибке.
  - Конфликты в hosts блокируют запись, пока пользователь не решит.
  - Кодировка и переводы строк сохраняются (UTF-8/UTF-16/cp1251, CRLF).
  - Поврежденные маркеры останавливают работу с кодом 4.
  - Права администратора проверяются заранее, предлагается UAC.
  - TCPView скачивается только по HTTPS с сайта Microsoft, проверяется
    Authenticode и издатель; без подписи запуск запрещен.
  - Защита от zip-slip при распаковке.
  - Телеметрии нет; в сеть уходят только DNS/TCP/TLS-проверки и
    загрузка TCPView по команде.

9. ТЕСТИРОВАНИЕ
--------------------------------------------------------------------------------

Автотесты: 118 тестов на unittest, без сети и без прав администратора.

  test_hosts      блоки, конфликты, кодировки, CRLF, backup/restore,
                  идемпотентность, ошибки маркеров
  test_config     нормализация доменов, валидация, round-trip
  test_resolver   кэш и миграция, DNS-пакет, стратегии, мертвый кэш
  test_scanner    netstat IPv4/IPv6, tasklist CSV, фильтры состояний
  test_i18n       совпадение ключей и placeholder'ов en/ru
  test_security   разбор subject сертификата, издатель Microsoft,
                  отказ для посторонних организаций
  test_cli        парсер, JSON, status/cleanup, apply с фейковым
                  резолвером и TLS, откат, аргументы UAC

Ручная проверка на тестовой машине:
  - status распознал два блока, созданных v2.3;
  - cleanup --dry-run посчитал их;
  - apply github_access --dry-run нашел реальную конфликтующую строку
    в hosts и не изменил файл;
  - портативный exe запускается и проходит config --check;
  - свежая распаковка релизного архива и запуск --version — код 0.

Результат: все 118 тестов проходят, сборка воспроизводима, релиз проверен.

--------------------------------------------------------------------------------
11. ОГРАНИЧЕНИЯ
--------------------------------------------------------------------------------

  - Закрепляются только IPv4-адреса.
  - Браузеры с DoH могут игнорировать hosts.
  - Адреса CDN меняются; фикс не вечен.
  - expected_issuers — эвристика, не certificate pinning.
  - Нужны права администратора для записи hosts.
  - Exe не подписан коммерческим сертификатом (SmartScreen).
  - Однофайловая версия требует записи в %TEMP%.
  - Если провайдер/сервис блокирует IP, hosts не поможет: нужен другой канал.
  - Поддержка только Windows.
