1. ЧТО ЭТО ТАКОЕ
--------------------------------------------------------------------------------

NetGuardian помогает, когда программа не может установить соединение:
долго висит на "подключении", показывает ошибку сети или таймаут, хотя
интернет работает.

Причина часто в том, что домен (например, github.com) резолвится в
недоступный или неправильный IP-адрес. NetGuardian:

  1) находит IP-адрес, который реально принимает TCP-соединение;
  2) закрепляет этот адрес за доменом в системном файле hosts;
  3) проверяет, что по новому маршруту работает TLS и сертификат;
  4) при неудаче автоматически откатывает изменения.

Все изменения обратимы: программа пишет в hosts отдельные помеченные блоки,
перед записью делает резервную копию, а командой cleanup удаляет только
свои блоки.

ВАЖНО: NetGuardian — не VPN и не средство обхода блокировок. Это
инструмент точечного исправления маршрута "домен -> IP" через hosts.


--------------------------------------------------------------------------------
2. СИСТЕМНЫЕ ТРЕБОВАНИЯ
--------------------------------------------------------------------------------

  - Windows 10 или Windows 11 (64-бит).
  - Права администратора для изменения файла hosts.
  - Около 20 МБ свободного места (портативная версия).
  - Для запуска из исходников: Python 3.9 или новее.

Права администратора нужны только для операций записи в hosts:
apply, cleanup, restore. Команды scan, status, validate, diag, config
работают и без них.

3. УСТАНОВКА И ПЕРВЫЙ ЗАПУСК
--------------------------------------------------------------------------------

3.1. ПОРТАТИВНАЯ ВЕРСИЯ (РЕКОМЕНДУЕТСЯ)
----------------------------------------

1) Распакуйте архив NetGuardian-3.1.1-portable-win64.zip в любую папку,
   например:
       C:\Tools\NetGuardian

2) В распакованной папке запустите run.cmd ОТ ИМЕНИ АДМИНИСТРАТОРА:
   правый клик по run.cmd -> "Запуск от имени администратора".

   Можно запускать и NetGuardian.exe напрямую, но run.cmd:
     - оставляет окно открытым при ошибке;
     - при необходимости переносит TEMP в папку пользователя.

3) Откроется меню. Для первого знакомства выберите:
       [7] Состояние — посмотреть текущие блоки и пути;
       [2] Применить профиль — выбрать профиль и применить;
       [3] Проверить маршруты — убедиться, что TLS работает.

ВАЖНО: не переносите NetGuardian.exe отдельно от папки _internal.
Портативная сборка состоит из exe и папки _internal рядом с ним.


3.2. ВЕРСИЯ ОДНИМ ФАЙЛОМ
------------------------

Файл NetGuardian.exe — та же программа в одном файле. При каждом запуске
она распаковывает встроенные библиотеки во временную папку (%TEMP%).
Если запись в %TEMP% запрещена (песочница, Controlled Folder Access,
ограниченная политика), окно закроется сразу.

В этом случае:
  - используйте портативную версию; или
  - запустите run.cmd: он подставляет TEMP в %LOCALAPPDATA%\NetGuardian\tmp
    и показывает код ошибки, не закрывая окно.

Если Windows показывает SmartScreen ("Windows защитила ваш компьютер"),
нажмите "Подробнее" -> "Выполнить все равно". Файл не подписан
коммерческим сертификатом; контрольная сумма указана в SHA256SUMS.txt.


3.3. ПЕРВЫЙ ЗАПУСК
------------------

При первом запуске рядом с программой создается файл routes.json —
конфигурация с четырьмя профилями:

    microsoft_fix   — Microsoft Edge / Windows Update
    github_access   — GitHub (web, API, raw, gist, codeload)
    gitlab_access   — GitLab (web и registry)

Если папка программы доступна только для чтения (например,
C:\Program Files), данные автоматически переносятся в:
    %LOCALAPPDATA%\NetGuardian

4. МЕНЮ
--------------------------------------------------------------------------------

  [1] Поиск зависших соединений
      Смотрит таблицу TCP-соединений Windows и ищет процессы, которые
      "зависли" в состояниях SYN_SENT, CLOSE_WAIT, FIN_WAIT_1/2 и т.п.
      Если находит — предлагает применить подходящий профиль.

  [2] Применить профиль
      Показывает список профилей. Для выбранного профиля находит рабочий
      IP для каждого домена, пишет блок в hosts и проверяет TLS.
      При ошибке проверки изменения откатываются.

  [3] Проверить маршруты (TLS)
      Для каждого домена профиля открывает TLS-соединение по закрепленному
      IP, проверяет цепочку сертификатов, издателя и срок действия.

  [4] Удалить исправления
      Удаляет один профиль или все блоки NetGuardian из hosts.
      Чужие строки не трогает.

  [5] Запустить TCPView
      Скачивает TCPView с сайта Microsoft (Sysinternals), проверяет
      цифровую подпись и запускает. Если подпись неверна, запуск
      отклоняется.

  [6] Диагностика соединения
      Проверяет домен по шагам: hosts -> системный DNS -> локальный DNS ->
      TCP -> TLS -> системный прокси. Выдает вердикт и рекомендацию.

  [7] Состояние и активные исправления
      Показывает пути, активные блоки, кэш адресов и количество
      резервных копий.

  [8] Резервные копии и восстановление
      Показывает копии hosts и позволяет восстановить любую из них.

  [9] Настройки
      Показывает пути, параметры, количество копий; может открыть папку
      с конфигурацией.

  [L] Переключить язык / Language
      Переключает русский и английский, выбор сохраняется в routes.json.

  [0] Выход
      Завершает работу. Изменения в hosts при этом остаются до cleanup.


--------------------------------------------------------------------------------
5. КОМАНДЫ КОМАНДНОЙ СТРОКИ
--------------------------------------------------------------------------------

Все возможности меню доступны командами. Это удобно для скриптов и
планировщика задач. Примеры:

  NetGuardian.exe status
  NetGuardian.exe scan
  NetGuardian.exe apply github_access
  NetGuardian.exe apply github_access --dry-run
  NetGuardian.exe validate
  NetGuardian.exe diag github.com
  NetGuardian.exe cleanup --all --yes
  NetGuardian.exe backups --restore 1
  NetGuardian.exe config --check
  NetGuardian.exe lang ru
  NetGuardian.exe --help
  NetGuardian.exe --version

Основные команды:

  scan                 найти зависшие соединения
  apply ИМЯ            применить профиль
  validate [ИМЯ]       проверить маршруты по TLS
  cleanup [ИМЯ]        удалить один профиль
  cleanup --all        удалить все блоки NetGuardian
  status               показать активные блоки, кэш, копии
  diag ДОМЕН           диагностика домена
  backups              список резервных копий
  backups --restore N  восстановить копию по номеру или имени
  tcpview              скачать/запустить TCPView
  config --check       проверить routes.json
  config --show        показать действующую конфигурацию
  lang ru|en|auto      переключить язык

Полезные параметры:

  --config ПУТЬ        свой файл routes.json
  --data-dir ПУТЬ      папка для кэша, логов и копий
  --hosts ПУТЬ         подменить путь к hosts (для тестов)
  --json               машиночитаемый вывод
  --no-color           без цветов
  --verbose            дублировать лог в консоль

Флаги apply:

  --dry-run            только показать план, ничего не записывать
  --force              игнорировать конфликтующие строки hosts
  --no-verify          не проверять TLS после записи

Коды возврата:

  0  успех
  1  ошибка выполнения (нет адресов, TLS не прошел и т.п.)
  2  ошибка конфигурации или аргументов
  3  нужны права администратора
  4  поврежден блок NetGuardian в hosts


--------------------------------------------------------------------------------
6. КОНФИГУРАЦИЯ routes.json
--------------------------------------------------------------------------------

Файл routes.json лежит рядом с программой (или в
%LOCALAPPDATA%\NetGuardian). Это обычный JSON.

6.1. БЛОК settings
------------------

  language            "auto", "en" или "ru". По умолчанию "auto".
  local_dns           IPv4 локального DNS; пусто = системный резолвер.
  dns_timeout_sec     таймаут DNS-запроса, секунды (1..30).
  tcp_timeout_sec     таймаут TCP-проверки, секунды (1..30).
  cache_ttl_hours     срок жизни кэша, часы; 0 отключает кэш.
  backup_keep         сколько резервных копий hosts хранить (1..100).
  verify_after_apply  true/false: проверять TLS и откатывать при ошибке.
  stuck_states        какие состояния TCP считать зависшими.

6.2. БЛОК profiles
------------------

Каждый профиль — именованный набор доменов и правил:

  description         описание для меню.
  domains             список доменов. Можно вставлять URL — путь отбросится.
  process_hints       подстроки имен процессов для команды scan.
  strategy            способ поиска адреса (см. ниже).
  static_candidates   общий список IPv4, которые проверяются первыми.
  domain_candidates   свои IPv4 для каждого домена (приоритет выше).
  expected_issuers    подстроки издателя сертификата (например, "DigiCert").
  ports               порты TCP-проверки, по умолчанию [443].

Стратегии:

  static_first        сначала domain_candidates/static_candidates,
                      затем локальный DNS, затем системный.
  dns_discovery_only  локальный DNS, затем системный.
  static_only         только domain_candidates/static_candidates, без DNS.
  system_dns          сначала системный резолвер, затем локальный DNS.

Кэш проверяется первым в любой стратегии. Закэшированный адрес все равно
проверяется TCP-подключением: если он умер, кэш сбрасывается.


6.3. GITHUB И GITLAB
--------------------

В 3.1 добавлены профили github_access и gitlab_access. Проверенные
адреса (тестовая сеть, 31.10.2026):

  github.com                  140.82.121.3/4, 140.82.112.3
  api.github.com              140.82.121.6
  raw.githubusercontent.com   185.199.108-111.133
  gist.githubusercontent.com  185.199.108-111.133
  codeload.github.com         140.82.121.9
  gitlab.com                  172.65.251.78
  registry.gitlab.com         35.227.35.254

Порядок:
  1) NetGuardian.exe diag github.com
  2) если в hosts есть строка "185.199.108.133 github.com" — удалите
     или закомментируйте её в блокноте от администратора;
  3) NetGuardian.exe apply github_access --dry-run
  4) NetGuardian.exe apply github_access
  5) NetGuardian.exe validate github_access

Строка 185.199.108.133 github.com — это GitHub Pages, а не web-фронт.
TLS с ней может проходить, но отдаётся не тот сайт, поэтому профиль
считает её конфликтом.

Если провайдер или сам сервис блокирует российские IP, hosts не
поможет: это ограничение сети/аккаунта. NetGuardian не подменяет IP
и не является VPN; решение об использовании VPN — за пользователем.


--------------------------------------------------------------------------------
7. БЕЗОПАСНОСТЬ И ОТКАТ
--------------------------------------------------------------------------------

Что NetGuardian делает с hosts:

  - добавляет блок с маркерами:
        # === NETGUARDIAN FIX (profile) [timestamp] BEGIN ===
        IP domain
        # === NETGUARDIAN FIX (profile) [timestamp] END ===

  - перед каждой записью создает копию в папке backups;
  - пишет файл атомарно (временный файл + замена), чтобы сбой не
    оставил половину hosts;
  - перечитывает файл и сверяет блок;
  - при неудачной TLS-проверке восстанавливает предыдущую версию.

Что NetGuardian НЕ делает:

  - не удаляет и не комментирует чужие строки hosts;
  - не меняет настройки DNS, прокси, firewall;
  - не устанавливает службы и драйверы;
  - не отправляет данные в интернет (кроме загрузки TCPView по запросу).

Конфликты. Windows использует первое совпадение в hosts. Если выше блока
уже есть строка "другой IP этот-домен", фикс не сработает. NetGuardian
находит такие строки и отказывается писать, пока вы их не удалите или не
закомментируете. Флаг --force пишет блок, но чужая строка все равно может
выигрывать — используйте его осознанно.


--------------------------------------------------------------------------------
8. ЧАСТЫЕ ПРОБЛЕМЫ
--------------------------------------------------------------------------------

8.1. "NetGuardian.exe не запускается", окно закрывается сразу
-------------------------------------------------------------
Однофайловая версия не смогла распаковать библиотеки в %TEMP%.
Используйте портативную версию (папка NetGuardian) или run.cmd.
Подробности — в разделе 3.2.

8.2. "Access denied" при записи hosts
--------------------------------------
Запустите от имени администратора. В меню программа сама предложит
перезапуск через UAC.

8.3. "Existing hosts entry conflicts..."
----------------------------------------
В hosts уже есть строка для этого домена с другим IP. Удалите или
закомментируйте ее в блокноте от администратора, затем повторите apply.
Либо примените --force, если уверены.

8.4. validate показывает UNTRUSTED
----------------------------------
TCP работает, а TLS нет. Обычно это прокси, VPN или антивирус с
перехватом трафика. Запустите diag ДОМЕН и посмотрите системный прокси.

8.5. apply пишет "no reachable address"
---------------------------------------
Ни один адрес не принял TCP на указанном порту. Проверьте сеть,
local_dns, static_candidates и ports.

8.6. Браузер игнорирует hosts
-----------------------------
Chrome, Edge и Firefox могут использовать собственный DNS-over-HTTPS
(Secure DNS) и не смотреть в hosts. Отключите Secure DNS в настройках
браузера или проверяйте маршрут через diag/validate.

8.7. Старые блоки версии 2.3
----------------------------
Они читаются и удаляются: NetGuardian.exe cleanup --all.
Формат маркеров совместим.

8.8. Программа установлена в Program Files
------------------------------------------
Конфигурация, кэш, логи и копии автоматически уходят в
%LOCALAPPDATA%\NetGuardian. hosts все равно требует администратора.


8.9. GitHub не открывается
--------------------------
Проверьте diag github.com. Частая причина — старая строка
"185.199.108.133 github.com" в hosts: она перекрывает блок NetGuardian.
Удалите/закомментируйте её и примените github_access. Подробнее — 6.3.

9. ГДЕ ХРАНЯТСЯ ДАННЫЕ
--------------------------------------------------------------------------------

  routes.json         настройки и профили
  cache_ips.json      кэш найденных адресов
  logs\               логи (netguardian.log, ротация 1 МБ x 3)

Все это лежит рядом с программой. Если папка только для чтения —
в %LOCALAPPDATA%\NetGuardian.


--------------------------------------------------------------------------------
10. КАК УДАЛИТЬ ПРОГРАММУ
--------------------------------------------------------------------------------

1) Удалите свои блоки из hosts:
       NetGuardian.exe cleanup --all

2) Удалите папку программы.

3) При желании удалите данные:
       %LOCALAPPDATA%\NetGuardian

Резервные копии hosts останутся в папке backups — их можно хранить
отдельно или удалить вручную.

11. ПРОВЕРКА ЦЕЛОСТНОСТИ
--------------------------------------------------------------------------------

В архиве есть файл SHA256SUMS.txt. Проверить файл в PowerShell:

    Get-FileHash .\NetGuardian.exe -Algorithm SHA256

Сравните значение с указанным в SHA256SUMS.txt. Для архива проверяйте
сам zip тем же способом.
