## 3.1.4 — Проверка версии при запуске

**Зачем.** Пользователь запускает старую сборку и не знает, что вышла новая.
Обратной связи у программы нет: она работает локально и никуда не ходит.

**Что делает.** При старте (не блокируя работу) спрашивает у GitHub последний релиз
и, если он новее текущего, показывает одну строку: «доступна 3.1.4, скачать: <url>».

### Решения, которые надо принять при реализации

| Вопрос | Предлагаемое решение | Почему |
|---|---|---|
| Источник | `GET https://api.github.com/repos/Svetliak38/netguardian/releases/latest`, поле `tag_name` | Отдаёт и версию, и ссылку; без токена; репозиторий публичный |
| Когда | при запуске, в фоне, не задерживая меню | Проверка не должна влиять на работу |
| Как часто | не чаще раза в 24 часа, кэш в `data/update.json` | Экономит запросы и не раздражает |
| Офлайн | молча пропустить, **не** показывать ошибку | Отсутствие сети — нормальный режим, а не сбой |
| Отключаемость | настройка `update_check: true` и флаг `--no-update-check` | Пользователь вправе не ходить в сеть |
| Таймаут | 3–5 с, отдельный от диагностических | Не вешать запуск на медленном канале |
| Приватность | GET без идентификаторов, `User-Agent: NetGuardian/<version>` | Запрос не должен выдавать пользователя |
| Сравнение версий | семантическое, не строковое | `3.1.10` новее `3.1.9`, а строка скажет обратное |
| Действие | только показать ссылку, **ничего не скачивать и не запускать** | Автообновление без проверки подписи — это дыра |
| Rate limit | учитывать `403`/`429` и молчать | 60 запросов в час на IP легко исчерпать |

### Границы

- Новых зависимостей нет: `urllib` + `json`, как в остальном проекте.
- Сеть только по явному вызову; при импорте модуля — ни одного запроса.
- Работает в собранном exe (PyInstaller), не только из исходников.
- i18n: две строки (есть обновление / ошибка не показывается), RU и EN.

### Что считается готовым

1. `netguardian/update.py` с `check(current_version) -> UpdateInfo | None`.
2. Настройка `update_check` в `Settings` с валидацией, как у `pin_mode`.
3. Вывод в `menu` и в `--version`/`status`; в `--json` — поле `update_available`.
4. Тесты: доступна новая версия, версия та же, сеть недоступна, ответ 403/429,
   кэш не даёт долбить API, сравнение `3.1.10` vs `3.1.9`.
5. Офлайн-прогон: ни одного предупреждения в консоли.

### Риски

- Корпоративные прокси и фильтры могут отдавать не JSON — разбор должен быть терпимым.
- Кэш в `data/` может оказаться на read-only носителе — падать нельзя.
- Если добавлять автоскачивание, то только со сверкой SHA-256 из `SHA256SUMS.txt`
  релиза и проверкой подписи; до этого — не добавлять.
